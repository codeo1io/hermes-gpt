### Cycle 3 learnings — prevention rules (run 0c8974179349; rules 1-10 from prior cycles remain in force)

1. **Persisted-state importers are unauthenticated write paths.** import_dynamic_clients previously skipped every check that live registration enforces — a tampered durable store silently regained grant power on restart. Any future "restore from disk" path must revalidate at full live-write parity (schema, prefix, allowlists, capacity) or reject loudly with a reason, and a test must prove a hostile payload cannot smuggle state in.
2. **Capacity without eviction is a DoS design, not a safeguard.** A registry cap on an unauthenticated endpoint only converts permanent exhaustion into temporary exhaustion if paired with TTL eviction AND expiry-aware lookups AND reclaim-before-admission (register calls cleanup() first). New bounded registries ship all four properties together, with a fill-beyond-cap-and-recover test.
3. **After any auth-surface merge, grep the docs for negated claims.** The only HIGH-severity assess finding was a docstring/docs sentence ("no dynamic client registration") contradicted by merged code. Negation phrases ("no X", "does not support X", "never") rot fastest; check them explicitly at reconciliation time, and pair every new env knob with its .md documentation in the same change-unit.
4. **Baseline counts are environment-bound; zero-delta claims need a same-tree A/B.** The assess baseline 1497P/28S did not reproduce in the implementation worktree (1486P/5S pre-change). The durable proof shape is: stash-probe the pre-change tree in the SAME worktree+interpreter, diff the collected/run counts, and account for every delta by name (+14 new tests here). Full-suite "1497→1500" comparisons across environments are not evidence.
5. **Judge suite health by exit code; capture counts with `-o addopts=`.** Repo addopts `-q` suppresses pytest's summary line, so a green run prints no counts at all — a bare `pytest -q` log cannot prove pass counts. Run the authoritative shape with `-o addopts= -q` when the count itself is the evidence.
6. **Fixed-suffix staging files are a concurrency hazard class.** `path.with_suffix(".tmp")` writers race when two writers target one path; the repo still has 12 such sites (operator_swarm:565, operator_config:330/439/615, operator_codex:57/92, operator_session:67, token_store:127/243, codex_config:167/240, operator_runners:85). New or touched atomic writers use the unique-tmp+fsync+cleanup-on-failure pattern (see operator_job_supervisor.py:76 and now _atomic_write_text/_write_jobs); migrate the rest under rm-039's remainder.
